# TokenJuice 빠른 출시·피드백 운영 계획

확인일: 2026-10-09  
목표: 실제 사용자를 빠르게 확보하고, 설치·표시·신뢰성 문제를 주간 릴리스로 반영한다.

## 실행 체크포인트 — 2026-10-10

- 공개 Pocket은 `4d326d3`/offline cache v11, desktop release는 immutable `v1.2.2`다.
- 최신 엔진 후보는 Claude/Codex 잘못된 사용률·미래 관측 시각을 차단하고 오류 원인·성공
  시각을 desktop renderer와 일치시킨다. local provider의 실패 읽기도 성공으로 표시하지 않는다.
  로컬 80개 테스트/1043 assertions 및
  release-verify는 승인된 플러그인 한 파일 갱신 뒤 설치본 일치까지 exit 0이다. 실제 UI는 pending이다.
  소스/CI 통과를 노트북 표시 문제의 해결 또는 스토어 출시로 기록하지 않는다.
- 다음 P0는 UI 접근/사용자 관찰로 노트북의 메뉴바/패널·
  quota/trust·절전 복귀 확인이다. 코드 mismatch만으로 미표시 원인을 확정하지 않는다.
- 이후 실기기 검증 결과를 바탕으로 patch 후보를 결정한다. tag/release 및 스토어 제출은
  이번 코드 push에 포함하지 않는다. 신규 사용자 5명·인터뷰 10명·14일 diary 결과는 pending이다.
- 전체 작업 내용 resume, 7일 trend/Coach, Windows toast, 자동 sync·모바일 설정과 native
  widget/스토어는 각각 데이터·동의·제품·플랫폼 계약이 필요하다. metadata-only 안내를
  전체 작업 복원으로 홍보하지 않는다. 상세 코드/CI·설치 일치와 남은 입력은 `REQUIREMENTS_AUDIT.md` §9.18이다.

## 1. 출시 전략

TokenJuice는 현재 모든 플랫폼에 같은 형태로 출시할 수 없다. 제품의 핵심 엔진은 로컬 파일과 OS 메뉴바/트레이를 읽기 때문에, 배포 채널을 다음처럼 분리한다.

| 트랙 | 지금 가능한 형태 | 목표 | 판정 |
|---|---|---|---|
| Web/PWA | GitHub Pages의 TokenJuice Pocket | 가장 빠른 공개 베타와 사용성 인터뷰 | 즉시 진행 |
| macOS | GitHub Release + 설치 스크립트/SwiftBar | 네 노트북에서 설치·표시가 성공한 뒤 공개 베타 | P0 차단 |
| Windows | GitHub Release의 exe + 설치 안내 | 실기기 트레이 검증 후 공개 베타 | P1 |
| Chrome/Edge 확장 | 현재 구현 없음 | 브라우저 안의 AI 사용량/세션을 추적할 명확한 사용 사례 검증 후 결정 | 보류 |
| Mac App Store | 현재 SwiftBar 플러그인 구조로는 바로 제출 불가 | 독립 macOS 앱·서명·공증·스토어 메타데이터 구축 | 별도 트랙 |
| Google Play | 현재 PWA는 Play 앱이 아님 | PWA 사용성 확인 후 TWA 또는 네이티브 Android 래퍼로 내부 테스트 | 별도 트랙 |

**중요:** GitHub Pages를 공개 베타로 먼저 운영하는 것은 App Store/Google Play 출시를 포기하는 것이 아니다. 스토어 심사 때문에 실제 피드백을 몇 주 늦추지 않기 위한 순서다.

## 3. 빠른 배포 순서

### 1단계 — 공개 베타

대상은 Claude Code 또는 Codex를 매일 사용하는 Mac 개발자다. GitHub Pages에서 Pocket을 체험하게 하고, GitHub Release에서 Mac/Windows 설치본을 제공한다.

성공 기준:

- 사용자가 5분 안에 제품 목적을 이해한다.
- Mac 사용자가 설치 후 메뉴바에서 상태를 확인한다.
- 실패한 사용자가 원인을 설명할 수 있는 진단 정보를 얻는다.
- 피드백 10건 이상을 모아 반복 문제를 분류한다.

### 2단계 — Mac/Windows 안정화 릴리스

실기기에서 설치·실행·재시작을 확인한 뒤 `v1.2.x` patch를 발행한다. 자동 테스트 통과만으로 실기기 통과를 대체하지 않는다.

### 3단계 — 스토어 준비

#### Mac App Store

현재 SwiftBar 플러그인을 그대로 등록할 수 없다. 독립 앱으로 다음을 별도 구현해야 한다.

- 메뉴바 앱 lifecycle
- 앱 샌드박스·권한·Keychain 접근 검토
- Apple Developer 서명·공증·App Store Connect 메타데이터
- 개인정보 라벨과 지원 URL
- 심사에서 비공식 provider endpoint 사용을 설명할 정책

#### Google Play

현재 Pocket은 정적 PWA다. 먼저 모바일 사용 패턴을 확인하고, 필요성이 확인될 때 TWA 또는 네이티브 Android 래퍼를 선택한다.

- package name·앱 아이콘·스토어 설명
- Data safety와 개인정보처리방침
- 내부 테스트 → 비공개 테스트 → 공개 출시
- 파일 import 및 오프라인 보관 검증
- 자동 로그인·자격증명 저장을 하지 않는다는 경계 유지

#### Chrome/Edge 확장

확장프로그램은 Mac 로컬 파일과 메뉴바를 대체하지 못한다. 다음 중 명확한 사용 사례가 확인될 때만 만든다.

- 브라우저에서 AI coding provider의 리셋/한도를 보는 기능
- 특정 웹앱의 세션 완료·승인 대기 알림
- Pocket의 snapshot import를 브라우저 작업 흐름에 연결하는 기능

사용 사례 없이 단순히 출시 채널을 늘리기 위한 확장은 만들지 않는다.

## 4. 피드백 데이터와 지표

초기에는 서버 분석 SDK를 넣지 않는다. 사용자가 직접 제보하거나 진단 정보를 복사하는 방식으로 시작한다.

| 지표 | 의미 | 목표 |
|---|---|---:|
| 설치 시작 → 첫 상태 표시 | 실제 핵심 가치 도달 여부 | 80% 이상 |
| 5분 내 설치 성공 | 온보딩 난이도 | 80% 이상 |
| stale/auth 상태를 올바르게 이해 | 신뢰 UX | 80% 이상 |
| 경고 후 checkpoint/resume 행동 | 제품이 작업 중단을 줄이는지 | 30% 이상 |
| 2주 재방문 | 반복 가치 | 인터뷰로 기준 설정 |

## 5. 출시 판정

다음 조건을 모두 만족해야 “실제 출시”라고 부른다.

- 네 Mac에서 설치 → 메뉴바 표시 → 실제 데이터 표시가 성공한다.
- 최소 5명의 신규 사용자가 별도 설명 없이 설치를 시도한다.
- 데이터가 없거나 오래된 경우에도 화면이 원인과 행동을 설명한다.
- 릴리스 페이지에 알려진 제한을 숨기지 않는다.
- App Store/Google Play는 심사 완료 전까지 “준비 중”으로 표시한다.

현재 판정은 **공개 PWA 베타 가능 / Mac 실사용 출시 차단 / 스토어 출시 준비 전**이다.
