## 1. 출시 전략

현재 채널 판단은 [경쟁 지도 §7~§10](COMPETITOR_GAP_MAP_2026-10-11.md#7-경쟁사-출시-채널과-가격-비교)을 우선 적용한다. C01~C05로 desktop 베타 연결·복구·설치·UI·피드백을 개선하면서 C06 Android 직접 연결·위젯을 설계한다. 수동 Pocket 포장을 모바일 live tracker 완료로 인정하지 않으며 C08 서명 AAB·내부 테스트·제출 준비 목표를 유지한다. TWA/오프라인 래퍼/네이티브 선택은 미확정이다. 아래 채널 표는 현재 가능한 배포 형태이지 최종 범위를 축소하는 결정이 아니다.

2026-10-10 로컬 후보 검토 패키지를 별도로 준비했다. 고정 source archive·동일 CI의
Windows exe/engine·검증 키트·SHA256SUMS·알려진 제한을 포함하며 설치/공개 배포·스토어
제출은 하지 않았다. 출처·해시·전체 TODO별 완료/차단은 [후보 검토 원장](RELEASE_CANDIDATE_REVIEW.md)
참조. 스토어 서명 앱/AAB/확장 패키지가 준비됐다는 뜻은 아니다.

TokenJuice는 현재 모든 플랫폼에 같은 형태로 출시할 수 없다. 제품의 핵심 엔진은 로컬 파일과 OS 메뉴바/트레이를 읽기 때문에, 배포 채널을 다음처럼 분리한다.

| 트랙 | 지금 가능한 형태 | 목표 | 판정 |
|---|---|---|---|
| Web/PWA | GitHub Pages의 TokenJuice Pocket | 가장 빠른 공개 베타와 사용성 인터뷰 | 즉시 진행 |
| macOS | GitHub Release + 설치 스크립트/SwiftBar | 네 노트북에서 설치·표시가 성공한 뒤 공개 베타 | P0 차단 |
| Windows | GitHub Release의 exe + 설치 안내 | 실기기 트레이 검증 후 공개 베타 | P1 |
| Chrome/Edge 확장 | 현재 구현 없음 | 브라우저 안의 AI 사용량/세션을 추적할 명확한 사용 사례 검증 후 결정 | 보류 |
| Mac App Store | 현재 SwiftBar 플러그인 구조로는 바로 제출 불가 | 독립 macOS 앱·서명·공증·스토어 메타데이터 구축 | 별도 트랙 |
| Google Play | 현재 PWA는 Play 앱이 아님 | PWA 사용성 확인 후 TWA 또는 네이티브 Android 래퍼로 내부 테스트 | 별도 트랙 |

**중요:** GitHub Pages를 공개 베타로 먼저 운영하는 것은 App Store/Google Play 출시를 포기하는 것이 아니다. 스토어 심사 때문에 실제 피드백을 몇 주 늦추지 않기 위한 순서다.

### 운영자 이슈 검토

저장소에서 `bun scripts/feedback-triage.mjs --live`를 실행하면 열린 이슈의 검토 대기열을 JSON으로 출력한다. GitHub CLI 인증이 필요하다. 이 명령은 이슈 번호·URL·라벨·상태·갱신 시각만 요청하며 제목·본문·작성자·댓글·진단 로그는 가져오지 않는다. 조회 실패는 exit 1이며 빈 성공 보고서로 바꾸지 않는다. 조회 상한 도달 시 전체 목록이 아님을 표시한다. 파일 저장·외부 게시·라벨 변경·스케줄 생성은 하지 않는다.

운영자가 재현 증거를 검토한 뒤 아래 라벨을 결정한다. 라벨이 없거나 같은 필드의 라벨이 충돌하면 자동 추정하지 않고 review 대기열에 남긴다. 이 도구는 라벨 생성·부착을 대신 실행하지 않는다.

| 필드 | 라벨 |
|---|---|
| 영역 | area:install / area:data / area:ux / area:feature |
| 우선순위 | priority:p0 / priority:p1 / priority:p2 |
| 진행 | status:needs-info / status:ready-to-fix / status:in-progress / status:verify |

검토 순서는 미분류 확인 → 비밀값 없는 재현 증거 확인 → 영역·우선순위·진행 상태 결정 → 수정 PR/커밋 연결 → 회귀 테스트 → 실제 해당 환경 확인 → 릴리스와 수정 버전 안내다. 개인정보 노출·잘못된 quota는 우선 검토하되, 분류 도구가 본문 없이 심각도를 판정하지 않는다. 7일 이상 갱신되지 않은 이슈는 재검토 대상으로 표시한다. 같은 영역의 이슈 두 건을 같은 오류나 서로 다른 사용자 두 명으로 계산하지 않는다. 반복 재현 판정에는 독립 보고와 재현 조건의 수동 확인이 필요하다.

2026-10-11 실제 조회에서 열린 이슈는 0건이었다. 미로그인 방문자의 제보 링크는 GitHub 로그인으로 이동한다. 제보 접수 성공·실사용 만족도·주간 반복 운영은 이 조회로 검증되지 않는다. 실제 제보나 인터뷰를 꾸며 넣지 않는다.

## 3. 빠른 배포 순서

Pocket 제보 후속: 하단 **피드백** 또는 **문제 제보 준비**에서 유형·재현 설명을 입력하고
공유 JSON을 먼저 확인한다. 상태 요약은 opt-in이며 계정/프로젝트/raw 대신 제한된 범주만
포함한다. 검토 뒤 복사/저장하고 고정 GitHub feedback.yml 양식에 직접 붙여넣어 제출한다.
자동 업로드·Local Storage 보관·접수 완료 표시는 없다. 이 동선 구현을 실제 사용자 제보
접수·응답·수정·재배포 1건이나 인터뷰 완료로 처리하지 않는다. DATA_CONTRACT의 Pocket
제보 초안을 따른다.

### 1단계 — 공개 베타

대상은 Claude Code 또는 Codex를 매일 사용하는 Mac 개발자다. GitHub Pages에서 Pocket을 체험하게 하고, GitHub Release에서 Mac/Windows 설치본을 제공한다.

성공 기준:

- 사용자가 5분 안에 제품 목적을 이해한다.
- Mac 사용자가 설치 후 메뉴바에서 상태를 확인한다.
- 실패한 사용자가 원인을 설명할 수 있는 진단 정보를 얻는다.
- 피드백 10건 이상을 모아 반복 문제를 분류한다.

### 2단계 — Mac/Windows 안정화 릴리스

실기기에서 설치·실행·재시작을 확인한 뒤 `v1.2.x` patch를 발행한다. 자동 테스트 통과만으로 실기기 통과를 대체하지 않는다.

### 3단계 — 스토어 준비

#### Mac App Store

현재 SwiftBar 플러그인을 그대로 등록할 수 없다. 독립 앱으로 다음을 별도 구현해야 한다.

- 메뉴바 앱 lifecycle
- 앱 샌드박스·권한·Keychain 접근 검토
- Apple Developer 서명·공증·App Store Connect 메타데이터
- 개인정보 라벨과 지원 URL
- 심사에서 비공식 provider endpoint 사용을 설명할 정책

#### Google Play

현재 Pocket은 정적 PWA이며 Android 프로젝트는 없다. [모바일 연결 출시 조건](MOBILE_CONNECTION_GATE.md)에 따라 계정별 허용된 수집·자동 전달·위젯을 검증한 뒤 패키지 방식을 결정한다. 수동 파일 앱 포장만으로 모바일 목표를 완료 처리하지 않는다. Claude 구독 로그인·토큰 중개 방식의 지원과 허용은 확인 전이며 이를 모바일 기본 인증으로 복제하지 않는다.

- package name·앱 아이콘·스토어 설명
- Data safety와 개인정보처리방침
- 내부 테스트 → 비공개 테스트 → 공개 출시
- 파일 import 및 오프라인 보관 검증
- 자동 로그인·자격증명 저장을 하지 않는다는 경계 유지

#### Chrome/Edge 확장

확장프로그램은 Mac 로컬 파일과 메뉴바를 대체하지 못한다. 다음 중 명확한 사용 사례가 확인될 때만 만든다.

- 브라우저에서 AI coding provider의 리셋/한도를 보는 기능
- 특정 웹앱의 세션 완료·승인 대기 알림
- Pocket의 snapshot import를 브라우저 작업 흐름에 연결하는 기능

사용 사례 없이 단순히 출시 채널을 늘리기 위한 확장은 만들지 않는다.

## 4. 피드백 데이터와 지표

초기에는 서버 분석 SDK를 넣지 않는다. 사용자가 직접 제보하거나 진단 정보를 복사하는 방식으로 시작한다.

| 지표 | 의미 | 목표 |
|---|---|---:|
| 설치 시작 → 첫 상태 표시 | 실제 핵심 가치 도달 여부 | 80% 이상 |
| 5분 내 설치 성공 | 온보딩 난이도 | 80% 이상 |
| stale/auth 상태를 올바르게 이해 | 신뢰 UX | 80% 이상 |
| 경고 후 checkpoint/resume 행동 | 제품이 작업 중단을 줄이는지 | 30% 이상 |
| 2주 재방문 | 반복 가치 | 인터뷰로 기준 설정 |

## 5. 출시 판정

공개 베타와 안정화 출시를 구분한다. 공개 베타도 실제 배포지만 아래 실기기·안전 조건을 생략하지 않는다.

- 네 Mac에서 설치 → 메뉴바 표시 → 실제 데이터 표시가 성공한다.
- 신규 사용자 5명 설치 시도는 공개 베타 후 안정화 검증이다. 모집·참여·결과는 실제 증거로 기록한다.
- 데이터가 없거나 오래된 경우에도 화면이 원인과 행동을 설명한다.
- 릴리스 페이지에 알려진 제한을 숨기지 않는다.
- App Store/Google Play는 심사 완료 전까지 “준비 중”으로 표시한다.

현재 판정은 **Pocket v26 공개 / Mac Claude 현재 인증 만료·전체 설치/복귀 미검증 /
운영형 AI 미개통 / 스토어 미출시 / 실제 인터뷰 미실행**이다. 과거 숫자 복구나 자동
검증 성공을 현재 수집 안정화·전체 출시 완료로 승격하지 않는다.
